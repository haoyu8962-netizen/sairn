# 布局完整性探针（截断与裁切检测）

状态：2026-11-21 试点。整体评分或页面级检查通过，不代表每个徽标、金额、标签都完整显示；这个探针逐个元素判断，补上「局部缺陷被整体结果掩盖」这一类验收缺口。思路来自大淘宝技术 2026-11-02 关于设计稿到三端真机验收的实践（整图评分过线、角标仍被裁切时必须退回修复），这里只取适用于 Web 夹具的部分。

## 它判断什么

`apps/terminal/tests/browser/layout-integrity.ts` 的 `findLayoutIntegrityIssues(page, { root, exceptions, tolerance })` 在浏览器里遍历 `root` 下每个渲染出来的元素，报告两类问题：

| 类别 | 判定 | 不算问题 |
| --- | --- | --- |
| `truncated` 截断 | 元素有自己的文字，内容比盒子宽（或高），而且溢出被隐藏：`overflow` 不是 visible、`text-overflow: ellipsis` 或行数截断 | 只是换行；元素本身可滚动（`auto`、`scroll`） |
| `clipped` 裁切 | 文字（按文字自身的范围计）或 svg、img、canvas、video 超出某个 `overflow: hidden` / `clip` 祖先的内边距盒 | 祖先可滚动；元素是 `position: fixed` 之类脱离裁切的情形不在本次判定范围内 |

不渲染的元素（`display: none`、`visibility: hidden`、零尺寸）和读屏专用内容（1px 的裁切盒）连同子树一并跳过。默认容差 1px，用来吸收亚像素取整。

每条结果给出 `区块 › «字段标签» › 标签名`：区块取最近的 `data-testid` 或 `data-slot`，字段标签取同一区块内前一个可见兄弟元素的短文字，方便直接定位到卡片里的哪一栏。

## 怎么用

1. 在夹具或页面测试里，等字体就绪（`document.fonts.ready`）、展开需要检查的折叠内容，再调用探针，`root` 取被测区域。
2. 覆盖规范要求的宽度（手机至少 320、375、393）、语言（至少 en 与 zh）和主题；数据要包含真实会出现的长值：强平方向文字、订单状态、大额金额、HIP-3 市场、现货交易对。
3. 断言结果为空。确实要接受的截断（例如设计上就省略的长地址并有完整的可访问名称）用 `exceptions` 按选择器登记，每条写理由。

`layout-integrity.pw.ts` 是探针自己的测试：用 `page.setContent` 构造省略号、行数截断、被裁的徽标与图标、读屏专用、可滚动、换行、隐藏和例外八种情形，逐一断言探针的结论。改探针时先跑它。

## 待处理清单

探针第一次接入的表面如果已有问题，不能为了让测试通过而放宽判定。做法与设计令牌棘轮和对话框提示条契约相同：把当前结果按 `类别 区块 «字段»` 写进测试里的待处理清单，清单必须与结果完全一致，新增问题会失败，修好一项也会失败，直到把它从清单删掉。清单同时写进任务记录的后续事项。

## 局限

- 只看浏览器实际渲染的几何，不判断换行后的排版是否美观，也不代替人看。
- Chromium 的结果不代表 iOS Safari 与 Android Chrome：字体回退和行高在真机上可能不同，换行与截断的临界宽度会变。真机或模拟器上的结论要单独记录，并写明构建版本。
- 选择器式的例外与按字段汇总的清单都依赖 `data-testid` / `data-slot` 和标签文字；标签改名会让清单失配，这时更新清单即可，不要放宽探针。
