# 布局完整性探针（截断与裁切检测）

状态：2026-11-21 试点，2026-11-24 复核。整体评分或页面级检查通过，不代表每个徽标、金额、标签都完整显示；这个探针逐个元素判断，补上「局部缺陷被整体结果掩盖」这一类验收缺口。思路来自大淘宝技术 2026-11-02 关于设计稿到三端真机验收的实践（整图评分过线、角标仍被裁切时必须退回修复），这里只取适用于 Web 夹具的部分。

## 它判断什么

`apps/terminal/tests/browser/layout-integrity.ts` 的 `findLayoutIntegrityIssues(page, { root, exceptions, tolerance })` 在浏览器里遍历 `root` 下每个渲染出来的元素，报告两类问题：

| 类别 | 判定 | 不算问题 |
| --- | --- | --- |
| `truncated` 截断 | 元素有自己的文字，内容比盒子宽或高，且对应轴的溢出被隐藏或省略 | 只是换行；对应轴可滚动（`auto`、`scroll`） |
| `clipped` 裁切 | 文字范围或 svg、img、canvas、video 超出某个 `overflow: hidden` / `clip` 祖先的内边距盒 | 可滚动容器内在该轴可到达的溢出内容；元素在某个轴上自己隐藏溢出时，超出它自己内边距盒的那部分文字（那是 `truncated`，不是祖先裁掉的） |

隐藏元素和读屏专用内容（1px 的裁切盒）连同子树跳过。零尺寸包装仍检查后代。`display: contents` 没有自己的布局盒，探针检查其文字范围与后代，也跳过它的 `overflow` 样式。默认容差 1px，用来吸收亚像素取整。

同一文件的 `findTableCellSpill(page, { root, tolerance })` 补上表格的第三类：`spilled`，单元格里的文字超出所在 `td` / `th` 超过容差，且从文字到单元格之间没有隐藏溢出或不可见的祖先（那种情况归上面两类）。`table-fixed` 表格里不换行的值放不下时会盖到相邻一栏，而不是被隐藏，`findLayoutIntegrityIssues` 看不到这种情况。路径是 `cell-spill › «列标题» › 标签名`。

每条结果给出 `区块 › «字段标签» › 标签名`：区块取最近的 `data-testid` 或 `data-slot`，字段标签取同一区块内前一个可见兄弟元素的短文字，方便直接定位到卡片里的哪一栏。另有 `anchor`：元素从 `root` 起的子元素序号路径（如 `0.3.1`）。同样的数据在每种界面语言下渲染出同样的元素树，所以它能跨语言对准同一个元素；`区块 › «字段标签»` 引用的是译文，做不到这一点。

## 怎么用

1. 在夹具或页面测试里，等字体就绪（`document.fonts.ready`）、展开需要检查的折叠内容，再调用探针，`root` 取被测区域。
2. 覆盖规范要求的宽度（手机至少 320、375、393）、语言（至少 en 与 zh）和主题；数据要包含真实会出现的长值：强平方向文字、订单状态、大额金额、HIP-3 市场、现货交易对。
3. 断言结果为空。确实要接受的截断（例如设计上就省略的长地址并有完整的可访问名称）用 `exceptions` 按选择器登记，每条写理由。

`layout-integrity.pw.ts` 用 `page.setContent` 验证省略号、行数截断、徽标和图标裁切、单轴滚动、无盒及零尺寸包装、读屏专用、换行、隐藏、例外和容差，以及元素自身隐藏的文字不再对祖先报裁切、`anchor` 的取值和 `findTableCellSpill`。改探针时先跑它。

## 待处理清单（首次接入过渡规则）

探针第一次接入的表面如果已有历史问题，不能为了让测试通过而放宽判定。做法与设计令牌棘轮和对话框提示条契约相同：按 `类别 区块 «字段» ×次数` 临时登记未修项并断言每组次数与清单一致；一张卡片可产生多条结果，次数相同的结果也可能出现在不同卡片。发现次数变化时，先查看原始定位与实际渲染，再调整清单，并在任务记录保留未处理项。问题清零后即移除清单，改为直接断言零发现（`expect(findings).toEqual([])`）。

历史做法说明：手机历史卡片在 2026-11-21 首次接入时曾使用上述按字段计数清单；该清单已随 2026-11-26 的修复清空并移除，现行手机历史夹具直接以零发现为通过条件，不再维护待处理清单。

## 局限

- 探针以普通布局中的 DOM 祖先和内边距盒估算裁切。脱离祖先裁切的固定定位、`overflow-clip-margin` 扩大的可见区、以及滚动视口本身被裁切，都需要在页面上复核。探针也不判断换行后的排版是否美观。
- 纵向截断按 `scrollHeight` 判断，绝对定位的伪元素也计入其中：手机当前委托卡片的市场按钮用 44px 的 `::after` 扩大触控区，被报成「内容高 31px、盒子 17px」，文字其实完整（2026-11-27 截图核对；合并 PR #21 的卡片布局后这个按钮不再触发）。这类结果在清单里注明，不当作截断修复。
- 拉丁、越南文与西里尔字母由 Inter / IBM Plex 网页字体绘制，各平台一致；中、日、韩、印地与阿拉伯文落到系统回退字体，账户表格夹具里这几种语言的读数只代表读取时的操作系统（2026-11-27 为 macOS 上的 Chrome）。
- Chromium 的结果不代表 iOS Safari 与 Android Chrome：字体回退和行高在真机上可能不同，换行与截断的临界宽度会变。真机或模拟器上的结论要单独记录，并写明构建版本。
- 选择器式的例外（以及首次接入表面若临时采用按字段汇总的过渡清单）都依赖 `data-testid` / `data-slot` 和标签文字；标签改名会让选择器或过渡清单失配，这时更新对应选择器或清单即可，不要放宽探针。
