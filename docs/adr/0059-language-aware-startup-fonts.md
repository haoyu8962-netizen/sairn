# ADR 0059：启动字体等待按语言带上非拉丁子集

- 状态：已在工作树实施（2026-11-27），分支 `claude/terminal-i18n-orchestration-587e12`，未合入、未发布。运营方 2026-11-27 选定方案 A。
- 关联：[ADR 0010](0010-blank-until-ready-startup.md)「补充（2026-09-16）：网页字体不做回退字体绘制」（`font-display: block` 与启动门控等字体）；[ADR 0052](0052-service-worker-startup-asset-cache.md)（启动资源缓存）；[i18n 展示规范](../i18n-presentation.md)；`.claude/rules/startup-rendering.md`；[任务记录](../work-memory/sessions/2026-11-26-terminal-seven-new-languages.md)。

## 背景

- Inter 声明了七个子集，IBM Plex Sans（`font-market-close`：头部、市场概览、代币选择器、账户表格、菜单、资金弹窗）只声明了拉丁子集。依赖包 `@fontsource-variable/ibm-plex-sans` 5.2.8 自带拉丁扩展、越南语、西里尔、西里尔扩展、希腊子集（13–31 KB），一直没声明。
- 启动门控 `StartupReadyGate` 与 `MarketOverview` 用 `document.fonts.load(spec)` 等字体。不带文字时浏览器按一个空格挑字体面，只加载拉丁子集。
- 2026-11-27 越南语审查（Codex 第 1 轮 P2）与运营方核对时按语言目录实际字符统计（重叠范围按最后声明的字体面算，CSS Fonts 4 `unicode-range`）：现有十种语言里只有越南语用到拉丁以外的子集（越南语子集 44 个字符，拉丁扩展 11 个，如 ă đ ơ ư）；法语的 œ 落在拉丁子集里。按字母表推断，土耳其语会用到拉丁扩展，俄语会用到西里尔。
- 结果：IBM Plex 界面上越南语带调字母逐字落到系统字体；Inter 界面上冷缓存首屏这些字母先不可见（`font-display: block`），子集到达后才出现。俄语界面会是整段文字。

## 决策

1. **IBM Plex 声明它自带的全部子集**：西里尔扩展、西里尔、希腊、越南语、拉丁扩展、拉丁，顺序和 `unicode-range` 与 Inter 同名子集一致。浏览器只在页面画到某个子集的字符时才下载它，不用这些字符的语言不多下载。
2. **每种语言为它用到的每个非拉丁子集列一个样例字符**：`LOCALE_FONT_SAMPLES`（`lib/fonts/font-readiness.ts`），现在只有越南语 `ạă`（ạ 只在越南语子集，ă 按最后声明落在拉丁扩展）。`fontTextForLocale` 在样例前加一个空格，让拉丁子集仍在等待之内；没有样例的语言照旧不带文字。
3. **启动门控按保存的语言等，市场概览按当前语言等**：两处都把这段文字传给 `fonts.check` / `fonts.load`，上限仍是 `FONT_READY_TIMEOUT_MS`（3 秒），与语言目录的加载并行。超过上限照旧先显示，与 `font-display: block` 的语义一致。
4. **语言菜单在意图时预热**：菜单用 IBM Plex 列出每种语言的母语名称（如「Tiếng Việt」）。语言按钮在指针进入、按下或获得焦点时调用 `warmFonts(LANGUAGE_MENU_FONT_SPECS, 全部语言名称)`，只发起加载、不等待；字体已可用时什么也不做。没有它，声明 Plex 越南语子集之后，英文用户第一次打开菜单时这些字母会先不可见。
5. **契约**：`locale-font-subset-contract` 从 `styles.css` 读两套字体的字体面，从每个语言目录读译文字符（不含文件头与废弃条目，遇到不支持的 PO 写法直接失败），按最后声明的字体面算出用到的非拉丁子集，要求样例用到的子集与之相等，且样例不会让 `load` 额外拉一个目录用不到的子集。各引擎为 `load(font, text)` 挑字体面的方式不同（Chromium、Firefox 收集与文字相交的所有字体面，WebKit 按字符取一个），所以样例为每个子集放一个「按最后声明就落在该子集」的字符，两种方式都会加载它；「额外子集」一项按「所有相交字体面」这个上界检查。`startup-font-display-contract` 要求 IBM Plex 的子集顺序与范围与 Inter 同名子集一致。

## 不做的事与理由

- **热切换语言不等待。** 在设置里第一次切到需要新子集的语言时，这些字母可能有一瞬间不可见；缓存保留时每台设备只发生一次，清缓存、缓存被淘汰或字体文件更新后会再出现。要避免它，可以只在语言菜单的切换入口先等子集再切换（不能放进 `dynamicActivate`，那样启动路径上语言目录的 3 秒上限会提前触发、以英文显示），代价是每次切换先做一次就绪检查，所需子集还不可用时切换要等它加载完或等到上限。这个取舍先选不等。
- **不按语言在 head 里预载。** 壳是预渲染的单份 HTML，不知道语言；要提前下载只能改内联启动脚本并带上带哈希的字体地址，CSP 哈希随之变化。冷启动多出的子集与语言目录并行下载，先不做，等真实网络下的启动测量再定。
- **Service Worker 不保留这些子集。** 启动资源缓存（ADR 0052）只保留壳列出的资源，运行时取到的子集在下次协调时会被清出资产缓存；字体文件是一年 immutable，第二次访问通常由浏览器 HTTP 缓存命中。把各语言子集列进壳会让每个用户都预取全部子集。
- **不把 `font-display` 换成 `swap`。** ADR 0010 的理由不变：回退字体绘制再换字会让头部与指标行重排。

## 代价

- **启动门控多等的下载**（按保存的语言，两套字体合计，woff2 原始字节）：越南语约 139 KB（Inter 越南语 10,252 + 拉丁扩展 85,068，Plex 越南语 13,160 + 拉丁扩展 30,964），土耳其语预计约 116 KB，俄语预计约 48 KB；其他语言不多等。对照：两套拉丁子集的预载合计 93,968 字节。
- **按内容的下载**：任何语言的页面画到某个子集的字符（代币名、标签、U+20A0–20C0 的货币符号等）时，浏览器照旧按需下载那个子集，冷缓存下这些字符在下载期间不可见（`font-display: block`）。以前 IBM Plex 界面上的这类字符直接用系统字体画；现在它们和 Inter 界面一样，先短暂不可见，再以 IBM Plex 显示。
- **语言菜单预热只是开始下载**：触屏按下后菜单立刻打开，子集未必已经到达；它缩短、但不保证消除首次打开时语言名称的不可见。
- 包体预算只计 JS 与 CSS，不计字体；样例表与预热逻辑进入入口代码，约数百字节。

## 验证

- 单测：`font-readiness`（带文字与不带文字的参数、预热）、`root-startup-fallback`（保存越南语时两套字体都带样例等待；拉丁字体与目录都已可用时仍等子集）、`market-overview`（越南语时两个规格都带样例）、`language-switcher-font-warm`（指针进入、按下、焦点三种意图都预热全部语言名称，之前不加载；预热之后键盘仍能打开菜单并切换语言，鼠标点击仍能打开菜单。jsdom 里脚本注入的 pointerdown/pointerup 无论有没有预热处理器都打不开这个菜单，所以「按下」路径只在浏览器里验证）、两个契约（PO 解析器另有自己的输入用例：不计文件头、注释与废弃条目，复数等不支持的写法直接失败）。变异：去掉样例中的 ă、删掉越南语样例、门控等待或初始检查不带文字、概览不带文字、去掉 Plex 越南语字体面、改动 Plex 一个范围、`load` 丢掉文字、语言按钮去掉焦点或指针进入预热，各自让对应测试失败，均已还原。
- 浏览器（2026-11-27，本机开发服务器，Playwright 无头 Chromium 与 WebKit，冷上下文，人为把每个非拉丁子集延迟 1.5 秒）：越南语两种引擎都在四个子集到达之后约 50 毫秒才显示真实界面（390 宽手机界面约 180–210 毫秒），显示时样例在两套字体上都可用；把门控临时改回不带文字的旧写法，Chromium 在子集到达之前显示，显示时样例不可用。子集延迟 6 秒时，页面在开始请求约 3 秒后显示（上限生效）。英文冷启动只下载两个拉丁子集；悬停语言按钮只多下载 IBM Plex 越南语子集，随后点击能打开菜单，「Tiếng Việt」的计算字体是 IBM Plex、字形可用。越南语在交易页、Portfolio、Earn、Vaults、Staking、Referrals、Leaderboard 的 1440、1100、390 宽下的截断扫描与补子集之前相同，只比英文多出 1440 宽订单簿列头一处。这是脚本注入的指针事件和开发服务器上的测量，不是生产构建、真实网络或真机。
