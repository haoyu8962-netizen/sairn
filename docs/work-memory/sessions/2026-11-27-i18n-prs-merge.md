# 七种界面语言 PR #22 与三个跟进 PR 的 CI 与合并核对

## 背景与范围

同步记录，2026-11-27，没有任务标识。

- **四个 PR**：
  - [PR #22](https://github.com/haoyu8962-netizen/sairn/pull/22)：七种新界面语言。
  - [PR #25](https://github.com/haoyu8962-netizen/sairn/pull/25)：有数据的账户表格在 14 种语言下的布局检查。
  - [PR #24](https://github.com/haoyu8962-netizen/sairn/pull/24)：三处 Market 改用带上下文的消息、土耳其语 `İ` 搜索、es/fr 写死的数字。
  - [PR #23](https://github.com/haoyu8962-netizen/sairn/pull/23)：订单簿 Size 列头单独译短。
- **运营方授权**：「先合并 #22，再合并另外三个」，之后又说「继续，合并完告诉我」。
- **分工**：编排会话负责合并。三个跟进分支先合入当时的 main、核对包体再推送；它们的会话把这次推送算在合并授权里，只推各自的 PR 分支。

经过、译文审查与验证见 [七种语言的任务记录](2026-11-26-terminal-seven-new-languages.md) 和 [账户表格检查记录](2026-11-27-account-tables-layout-integrity.md)。本记录只核对 CI 与合并。

## 结论与依据

### 合并顺序与核对

所有 PR 都用 merge commit 合并，合并时用 `--match-head-commit` 锁定头提交，没有开 auto-merge。

| 顺序 | PR | 合并时的头 | 头是否包含当时的 main | 最终头的 CI | 合并提交 |
|---|---|---|---|---|---|
| 1 | #22 | `739f20ca3` | 是（`4548175ea`） | 5 个工作流、8 个作业全部通过 | `7474813c3` |
| 2 | #25 | `afe03df06` | 包含 `7474813c3`，缺 #26（`1e2f21776`，只新增一份文档） | 4 个工作流、7 个作业全部通过（没改官网，所以不跑官网工作流） | `b9f07503d` |
| 3 | #24 | `a0201a440` | 是（`b9f07503d`） | 4 个工作流、7 个作业全部通过 | `1bcaaff49` |
| 4 | #23 | `70b3d95ed` | 是（`1bcaaff49`） | 5 个工作流、8 个作业全部通过（浏览器回归作业是第 2 次尝试） | `3bd9955c2` |

- **检查方式**：每个 PR 合并前都核对了 `gh pr view`（MERGEABLE、CLEAN），审查、议题评论和行内评论都是 0 条，用 `git merge-base --is-ancestor` 确认包含 main，并确认 `apps/website` 与 `brand/` 没有差异。
- **原有 7 个目录**（en/zh/ja/hi/es/fr/ar）：
  - #22、#25 没有改动。
  - #24 改了 es/fr 写死的数字（改回原文写法），并更新了三处 Market 条目的引用位置。
  - #23 增加了 Size 列头的上下文条目。
  - 两处都是运营方先前批准的待决项。
- **#25 没有先合入 #26**：#26 只新增一份文档，GitHub 报告没有冲突，所以 #25 的 CI 结果仍然代表合并后的内容。

### CI 失败与处理

- **#24 的第一个头 `bb7e92968`**：
  - **现象**：[run 45985443732](https://github.com/haoyu8962-netizen/sairn/actions/runs/45985443732) 的 `Test terminal and release tooling (2/2)` 只有 1 项失败（6,208 项通过）：`mobile-agent-sync-modal.test.tsx > reveals the QR after a two-second hold and closes the dialog after sixty seconds`，`expected "vi.fn()" to be called 1 times, but got 0 times`。
  - **会话的核实**：本分支没有改这个组件和它的测试，组件的导入链也不经过本分支改过的代码。本机单独连跑 5 次有 2 次整个文件失败，之后 9 次全部通过；6 份并行时 12 次全部失败，3 份并行时 9 次全部通过。整个文件失败的那些次都发生在后台构建期间，错误都是第一个用例冷加载组件超过 5 秒。CI 那种只在第 362 行失败的情况，本机没有复现。
  - **结论**：判断为负载导致的偶发超时。`docs/agent-handbook.md` 已经把这个文件列为高负载下会偶发超时的测试，测试未改。合入 main 后的新头 `a0201a440` 上，这个作业通过。
- **#23 的头 `70b3d95ed`**：
  - **现象**：[run 45994273108](https://github.com/haoyu8962-netizen/sairn/actions/runs/45994273108) 的 `Terminal browser regressions (1/2)` 在安装浏览器依赖时就失败了：`https://packages.microsoft.com/ubuntu/24.04/prod` 返回 `403 Forbidden`，Playwright 以 `exited with code: 100` 退出，测试没有开始。
  - **处理**：用 `gh run rerun --failed` 只重跑失败的作业，第 2 次尝试通过。这是运行机软件源的临时问题，代码没改。

## 验证与限制

- 每个 PR 的核对都是合并前用 `gh` 和 `git` 读取的远端状态：CI 结论、MERGEABLE/CLEAN、审查与评论数、是否包含 main、`apps/website` 与 `brand/` 的差异。合并后 main 上不会再跑 CI（工作流只在 PR、标签和手动运行时触发）。最后合入的 #23 已包含 main `1bcaaff49`，合并后的 main `3bd9955c2` 与 #23 测过的内容相同。
- #24 偶发失败的结论来自它的会话在本机的重跑，CI 那种失败形态没有复现。
- 没有发布：main 不等于线上，线上仍以最新的 `cloudfront-*` 标签为准。
- 没有构建生产发布配置（生产 `.env.local`、配对开），没有真机测试，没有母语审校。
